# Using the design set: start here

**Draft 3.3, 24 November 2026; provisional; not yet marked by the operator; one desk test of the reaction skill (on 3.1, two agents per version) and Codex source checks of 3.1 and 3.2; not used in a project yet.** Part of a set (`../README.md`, which also says what changed). Tags are warrants (`../WARRANTS.md`). To change a line, engage its warrant; to depart from one, see the core skill.

This skill is for whoever chooses what to load: a lead, or an agent working alone. An agent launched with its skills already named does not need it.

## Which skill for which moment

There is no fixed order. Load the one for the moment you are in, and go back to an earlier one when the work calls for it [schon-cycles] [suchman-instructions].

- **Always first,** except that a stop or a direct instruction takes effect before anything is loaded: `designing-with-a-person`, the core. Every skill below loads it.
- Nothing exists yet, or you are writing a brief for someone to build from: `starting-a-design`.
- A design, a skill or a method already exists and you are to work from it: `inheriting-a-design`.
- The person has said something about the work, yours or another agent's. A stop or a direct instruction takes effect as said, with nothing to load first; for anything else, load `reading-a-reaction` before you change the work in answer.
- You are to judge something another made: `critiquing-a-design`.
- You are handing work back, or calling the person back to decide: `reporting-design-work`.
- For how a thing should look and for platform conventions, use the project's own craft sources. This set does not cover them and does not replace them.

## When you launch an agent

- A skill that is not loaded does nothing. Name in the brief, or in the agent's definition, the skills it is to load; do not leave it to find them [vercel-not-invoked] [op-skill-never-loads].
- Give it the core and the one skill for its task. Do not give it this skill or the rest.
- Give a critic what the thing is for and its kinds of user, taken from the top of the brief (`starting-a-design`). `critiquing-a-design` tells it what to do when these are missing.
- What several agents were given in common is said in the report (`reporting-design-work`).

## Changing the set

- To change a line, engage its warrant in `../WARRANTS.md`, and keep the old line visible in the proposal.
- To depart from a line once, record it in the project's `design-set/DEPARTURES.md` with its ground (the core says how).
