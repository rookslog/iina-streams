# BUG-001 — Streamlink Bridge 0.1.0 reportedly does not work

Status: OPEN / UNREPRODUCED (user report accepted). Severity: blocks replacing the installed Bridge with copied code.
Environment: Apple M4 Apollo, IINA 1.4.4, Streamlink 8.6.3, mpv 0.41.0, yt-dlp 2026.08.19. Date: 2026-11-07.

## Known observations
The installed plugin lives at ~/Library/Application Support/com.colliderli.iina/plugins/local.iina.streamlink-bridge.iinaplugin. Manifest uses entry: main.js and globalEntry: global.js, with file-system and show-alert permissions. The per-player main.js is effectively empty; global.js creates three menu commands and starts Streamlink via iina.utils.exec and iina-cli.
Static syntax and manifest JSON passed earlier. The user reports the deployed implementation does not work. No evidence has yet established whether the menu appears, if click handler runs, whether Streamlink starts, or whether the playback process remains attached. Native terminal Streamlink-to-IINA playback succeeded on other channels before this report; irrelevant to plugin functionality.
The official IINA dev guide and installed known-good packages use globalEntry, while a different official documentation page shows global; this inconsistency is NOT evidence that the deployed key is wrong. Runtime observation is needed.
