## 5. Technical review: strengths and limits

### Strengths supported by source and tests

The core separates public source identity from transient media transport, reduces the exposed URL surface, and keeps quality replacement in the owned player. Generation checks defend against stale resolution and misleading file-loaded events. The explicit unconfirmed state is preferable to silently asserting a successful quality change after a timeout.

Chat has independent acquisition, authentication, timing, and presentation boundaries. Live chat uses arrival/server epochs; replay uses source offsets selected from actual mpv time. The implementations therefore do not accidentally advance historical chat with a wall-clock timer while video is paused. Import is streamed, disk-indexed, bounded, and atomically published; only safe generated chunk names enter the replay reader.

Native message serialization received a release-specific security review. IINA 1.5.1’s native-to-WebView bridge places JSON in a template literal, so raw JSON alone is insufficient. The percent-encoded envelope plus text-only DOM rendering addresses both the host bridge boundary and ordinary HTML injection. The global-controller tests also exercise numeric routing from native string labels, managed audience isolation, HTTP body semantics, and the corrected sender check for Forget.

The portfolio shares tested infrastructure and does not artificially reserve replay for B. Both presentations can use sidebar or overlay. Focus’s contextual inspector is a workflow difference; Unified offers faster access to playback settings while reading chat. Neither requires duplicate transport controls already supplied by IINA.

### Remaining risks and limitations

1. **Earlier reliability incidents remain unexplained.** Preserve the 19:45 mixed Twitch QA anchor closure,18:41/19:01 JSC sweep reports,18:04 Objective-C crash, historical Sidebar teardown, 19:56 More/Accessibility trap and separate 20:26 menu-tracking sample. Final ordinary YouTube cycles pass, but do not establish their causes or broad stability. Evaluation should remain bounded and isolated from stable use.
2. **Live auth and remembered login are deferred.** Native setup/rejection passes; no real read-only grant, IRC receipt, refresh/revocation or authenticated reconnect ran. Dummy Keychain write/read/clear failed. Session-only warning behavior is implemented, but successful authenticated session-only use still needs a legitimate grant. No plaintext fallback is shipped.
3. **Genuine Twitch replay provenance remains external.** Compatible import is implemented and tested with labeled fixtures; genuine YouTube replay does not certify Twitch history. Direct Twitch archival retrieval is not advertised. A legitimate archive is required for that end-to-end claim.
4. **Cancellation evidence has a defined scope.** Native replay-import Off stopped work and removed staging in1.795 s; ownership/publication races have real-subprocess and deterministic regressions. This does not prove every helper’s termination under every abnormal host exit. Imported user files must never be deleted by cleanup.
5. **Resource and duration limits matter.** Six short controlled modes exist, but unattributed WebKit, shared-system variance, sequential order and QA overhead preclude a total-efficiency winner. No energy, Safari-performance or long-session leak claim is made. The host retains managed player objects after close; clearing candidate timers is not proof that all RSS returns.
6. **Rendering/accessibility coverage is selective.** Plain text/emote text and selected historical message types are supported; rich image emotes and every edit/poll/gift renderer are not. Native drag/Done/click-through and constrained/fullscreen layouts were observed, but every keyboard, pointer-cancel, monitor, persistence and VoiceOver path was not audited.
7. **Native outer-sidebar collapse is not an explicit Off.** IINA 1.5.1 supplies no reliable plugin-sidebar collapse signal. Document occlusion is advisory; explicit Streams Hide/Off or teardown controls resources. Do not advertise cleanup merely because the outer panel is hidden.
8. **Preservation qualifications remain visible.** Original repository/plugin checks and candidate cleanup are separate. Safari’s preexisting window was resized during an optional comparison and only approximately restored because its original frame was not recorded. Native process/window experiments were scoped to test-owned instances. No blanket all-window-geometry or every-preference fingerprint claim is made.

Neither has a separate playback engine or intentionally missing replay/overlay capability. The detailed experience/tradeoff recommendation is in `SELECTION-REPORT.md`; the resource measurements do not justify choosing an efficiency winner.

The evaluation acceptance is conditional on these explicit boundaries:

- **Defer verified live chat and remembered-login claims** until a legitimate read-only grant is exercised. Native setup/error handling passes; dummy Keychain persistence did not. Session-only warning behavior is implemented, not a substitute for authenticated validation.

- **Retain the earlier reliability observations.** Eleven final ordinary YouTube cycles are bounded evidence, not a root-cause explanation of the earlier mixed-source anchor close/JSC/native-menu incidents or a long-session certification.
