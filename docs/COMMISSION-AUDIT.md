## 1. Current assessment

The source implements a substantial shared product foundation and two independently identified presentation configurations. Unified keeps playback controls and chat together; Focus makes the player and overlay primary and uses a contextual Playback/Chat inspector. Both receive replay and overlay capabilities. That is a defensible product distinction without withholding useful features from the baseline, although native comparison must demonstrate the difference in ordinary use rather than relying on configuration names.

The initial independent verification passed **82 JavaScript tests and 55 Python tests**. Actual native records establish Twitch VOD video and AAC playback, an operative quality control, and same-player quality replacement. Native testing found pause/window-geometry preservation defects; after the bounded sizing fix, both final Focus QA records now pass all eight assertions for 720p60→360p30 and the return to 720p60. Position 83.249667 s, pause, speed 1.5, one playlist item, and the 1180×720 frame at (180,170) remain unchanged. The completed Twitch recording removes the confounding behavior of a still-growing VOD from that check. This does not certify the eventual package bytes or untested fullscreen/hidden-sidebar cases.

The helper reviewer later reported **84 JavaScript tests and 70 Python tests passing** after the cancellation runner was added. This auditor's latest complete JavaScript run at approximately 18:40 passed **102/102** after the lifecycle/visibility, Connect-race, and bounded sizing fixes. These are working-copy results, not certification of a later package. Native Focus QA evidence now supports edit dragging without moving the IINA window, physical Done activation, constrained-window layout, and replay-import cancellation. The earlier invisible-overlay condition was overcome by an observed build containing explicit `overlay.setOpacity(1)` before `show()` and revised CSS; the evidence does not isolate its original cause. Controlled normal-mode click-through remains inconclusive, and both final production packages still need acceptance.

A genuine public YouTube archive was acquired and imported, and the later **Focus QA native** record now contains 51 passing checks against actual mpv time through beginning/near-end, forward/backward seeks, pause, 0.5×/2× rates, and an explicit offset. Its 693 messages are authentic archive data. The artifact explicitly says `fetchButtonTested:false`; packaged Fetch and final A/B parity remain separate gates. Native timing of a 100,000-message synthetic Twitch-format archive also passed, but a genuine Twitch archive has not established the end-to-end Twitch replay claim. Focus native records additionally establish Twitch live and ordinary/current-live/archived YouTube playback with active video/audio metadata and the original paused window unchanged. Codec metadata does not replace a listening test.

Live Twitch chat has a receive-only implementation and offline lifecycle coverage, but **no user Public Client ID or real OAuth grant has been used**. Its network/authentication acceptance gate remains external. Separately, the credential-free native Connect check exposed a global-to-child callback delivery defect: the broker produced `needs-client`, but the child stayed `authorizing`. A deferred, explicitly retained QA listener succeeded in a subsequent native probe; the production callback adjustment and native retest are in progress. This independently fixable host-integration gate must not be hidden under the missing-credential qualification. Root also reported a JavaScriptCore crash during the earlier probe sequence; temporal correlation has not established its cause.

**Current disposition: pending final native acceptance and packaging evidence.** Do not replace this with “Accept” merely because automated tests pass. Do not classify all pending rows as failures while the authorized test run is continuing.

## 5. Technical review: strengths and limits

### Strengths supported by source and tests

The core separates public source identity from transient media transport, reduces the exposed URL surface, and keeps quality replacement in the owned player. Generation checks defend against stale resolution and misleading file-loaded events. The explicit unconfirmed state is preferable to silently asserting a successful quality change after a timeout.

Chat has independent acquisition, authentication, timing, and presentation boundaries. Live chat uses arrival/server epochs; replay uses source offsets selected from actual mpv time. The implementations therefore do not accidentally advance historical chat with a wall-clock timer while video is paused. Import is streamed, disk-indexed, bounded, and atomically published; only safe generated chunk names enter the replay reader.

Native message serialization received a release-specific security review. IINA 1.5.1’s native-to-WebView bridge places JSON in a template literal, so raw JSON alone is insufficient. The percent-encoded envelope plus text-only DOM rendering addresses both the host bridge boundary and ordinary HTML injection. The global-controller tests also exercise numeric routing from native string labels, managed audience isolation, HTTP body semantics, and the corrected sender check for Forget.

The portfolio shares tested infrastructure and does not artificially reserve replay for B. Both presentations can use sidebar or overlay. Focus’s contextual inspector is a workflow difference; Unified offers faster access to playback settings while reading chat. Neither requires duplicate transport controls already supplied by IINA.

### Remaining risks and limitations

1. **Native parity and final package validation remain essential gates.** The Focus windowed quality retest now passes in both directions, and the source-class records are substantial evidence. Finish both workflows under comparable footage, final package bytes, hidden-sidebar/fullscreen quality cases, and controlled click-through. These independently achievable checks should not be handed to a future commission merely because the report is written.
2. **Live auth has both an integration defect and an external gate.** The no-client broker message failed to arrive natively; deferred/retained QA binding subsequently passed, and production repair is under test. That correctable delivery issue must be resolved independently of the registered Public Client ID/user approval prerequisite. No real read-only receipt, token refresh/revocation, Keychain credential cycle, or live reconnect has been observed. A correlated JSC crash is documented without an asserted cause.
3. **Twitch historical authenticity remains unestablished.** Compatible import is useful and implemented; full Twitch replay cannot be advertised from synthetic TwitchDownloader fixtures. Seek a legitimate real archive or state the exact unavailable source gate. The internal GraphQL approach was investigated, not promoted to an official stable API contract.
4. **Cancellation coverage remains specific to the tested path.** Native Focus replay-import Off now succeeded in 1.795 s total with no new staging/output. The helper reviewer subsequently reproduced a late-publication cancellation race; its ownership-safe repair and new regressions are still in progress at this update. Other helper kinds and native window-close cleanup need their own observations. The earlier missing signaling path is fixed; neither one native test nor the 50 ms polling interval proves all paths.
5. **Long-session and comparative resource claims remain unmeasured.** A bounded queue/cache is a useful architectural fact, not proof of low CPU/RSS or improved energy use. The release host retains managed child objects after window close and retains fired timeout dictionary entries unless explicitly cleared. The latter matters to the replay throttle and was reported for a narrow fix; neither finding establishes a measured RSS magnitude. Native WebKit retention, repeated open/close, and helper/disk cleanup need observation.
6. **Rich chat parity is intentionally limited.** Plain emote text, selected historical renderer types, and recorded removals are supported. There is no rich image-emote downloader or blanket support for every provider-specific event, edit, poll, or gifting format.
7. **Abnormal-termination artifacts need a removal policy.** Current source removes failed/superseded imports, fetched raw staging, and the active imported archive on window close; Off deliberately retains the selected archive for Resume. These changes address the earlier repeated-success accumulation concern. Native close cleanup and crash leftovers still need verification and candidate-owned removal instructions, without deleting user-supplied archives or another plugin’s data.
8. **Packaging documentation must choose the new build route.** Inherited `scripts/package-candidate.sh` targets `plugin-dev` and rewrites identity to `local.iina.streams`. It is not the Unified/Focus portfolio builder. Do not present or invoke it as the new candidate installation procedure.
9. **Native sidebar collapse has no reliable public visibility signal.** An occluded/Space-hidden WebView may report document.hidden while the sidebar remains the user's chosen presentation. The corrected policy preserves that session, and only explicit Streams Hide/Off or teardown stops it. Do not advertise automatic cleanup after IINA's outer collapse arrow; explain the distinction in usage and resource claims.

## 8. Final decision and recommendation rule

A provisional preference for **Unified** is defensible because it develops the user’s previously expressed preference and keeps quality available while reading chat. **Focus** is a serious alternative for video-first/fullscreen/background viewing and for reducing persistent panel space. It adds a step to reach the inactive inspector section; that tradeoff should be visible in the native comparison. The recommendation should not imply that B has fewer working features, that A is automatically safer because it is the baseline, or that separate engines were required.

Finalize the recommendation only after the same core acceptance conditions have been exercised in both configurations. For each candidate, give separate judgments on usability, visual coherence, native integration, feature completeness, interaction efficiency, accessibility, complexity, resources, reliability, maintenance, and extensibility. Shared implementation can support equal functional maturity; it cannot substitute for observing the different interactions.

Use the commission’s decision vocabulary explicitly:

- **Accept:** remaining work consists of stated external gates or genuinely minor refinements, with essential independently testable functionality and package/rollback paths verified.
- **Revise:** a specific correctable issue remains; name it, its user effect, and the next verification action.
- **Defer:** a concrete essential blocker prevents honest immediate evaluation/adoption.
- **Roll back:** evidence shows the candidate does not warrant replacing the preserved baseline.

At this cutoff, the correct entry is **pending final acceptance**, with the gates above being actively closed. The audit is not permission to stop. Any substantive, independently fixable defect found by the remaining native work should be corrected and rechecked before presenting the portfolio as near-release. Stable promotion still requires the user’s approval.
