## Findings (verbatim)

Verdict: SHIP AFTER FIXES. Do not merge and tag c3d6fd9 as-is. beta advanced to 24a048d during the review; none of the paths cited below changed.

### Findings

1. Blocker — The first release can strand users on a broken 0.5.4 source install. VERIFIED (IINA source + offline helper run). docs/RELEASE.md:52, ci.yml:53, src/io.js:8. Merging
   exposes ghVersion: 3 before tag CI publishes the asset, even if main and the tag are pushed together. IINA can then update a 0.5.3 install from main.zip, which still embeds the
   old helper. That helper rejected the new Twitch replay command in an offline run. Once installed with ghVersion: 3, it won’t be offered the correct package at the same version.
   Regenerate the checked-in helper and make the release asset available before exposing the update.

2. Important — Sign out can falsely report Twitch revocation. VERIFIED (mocked broker). src/player.js:73, global.js:106, src/auth.js:86. If Keychain saving failed and only one
   window is connected, Sign out disconnects first and discards the only in-memory grant. The marker write can then succeed and the broker reports revoked: true without making a
   revocation request. The marker itself correctly replaces a saved grant when the write succeeds.

3. Important — First-time Sign in doesn’t open Twitch automatically. VERIFIED (mocked auth and player). src/auth.js:16, src/player.js:321. The broker emits off before authorizing
   and waiting; the player clears the browser-open flag on off. The user is left at the code panel and must click the manual open button.

4. Important — Changing appearance can undo a saved Chat Off preference. VERIFIED (mocked reopen). src/player.js:106. Changing timestamps or layout rewrites settings without
   chatEnabled. A user upgrading with chat disabled can make an appearance change and then trigger automatic Twitch replay requests on the next VOD.

5. Important — A failed initial replay fetch drops a later seek. VERIFIED (mocked player). src/player.js:207. Seek while the first window is loading, then let that request fail:
   the player marks replay unavailable and discards the queued seek. It never tries the new position until the user manually retries.
