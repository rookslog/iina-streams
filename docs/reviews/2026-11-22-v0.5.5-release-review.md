## Brief (verbatim)

You are an independent release reviewer for IINA Streams, a JavaScript plugin for the IINA 1.5.1 video player on macOS. You are in your own Git worktree of the repository. First run `git fetch -q origin && git checkout -q --detach origin/release/0.5.5` there, and confirm HEAD is 9ef8f9e. Branch `release/0.5.5` (head 9ef8f9e) is the candidate. `main` is v0.5.4.

Decide whether `release/0.5.5` is fit to merge into `main` and tag `v0.5.5`. Review `git diff main...release/0.5.5` and the current files. Treat other agents' commit messages, CHANGELOG and docs as claims, not facts. Where a claim depends on IINA's behaviour, check it against IINA's source at tag v1.5.1 (github.com/iina/iina). Read-only `gh api` calls are allowed for that.

Lenses, in priority order:
1. **Security and privacy.**
   - New Twitch GraphQL and usher requests in plugin JS: `src/twitch-playback.js`, `src/resolve.js` and `main.js`. No token, signature or signed URL may reach a log, an error message or the UI.
   - The live clock (`src/live-clock.js`) polls a signed playlist URL; it must never log it.
   - Sidebar and overlay CSP now allow `img-src https://static-cdn.jtvnw.net`. Check that nothing wider is allowed and that message text never reaches `innerHTML`.
   - Settings backup on a parse failure (`src/io.js`), and auth diagnostics (`src/auth.js`, `global.js`): the codes only, never the contents.
   - **Moderation:** chat delay buffers live messages in the player (`src/player.js` live inbox, `ui/overlay-live.js`, `ui/live-history.js`). A message removed by Twitch moderation (clear-message, clear-user, clear-all) must never appear later, whether it was pending or already shown.
   - **QA-only code:** `global.js` and `main.js` contain QA probes (`qa-label-probe`, `player-open` and `open-error` traces). Confirm that each is inert unless `config.qa` is set, and that beta and stable builds set `qa:false`.
2. **Host contracts in IINA 1.5.1.**
   - The `on_load` hook must be an async function. IINA continues a non-async hook itself (`MPVController.swift` `MPVHookValue.call`).
   - `iina.http` casts params and headers to `[String:String]` and data to `[String:Any]` (`JavascriptAPIHttp.swift`).
   - `standaloneWindow.loadFile` clears listeners.
   - Menu submenus and key bindings.
   - No main-thread sync work on mpv's hook queue.
3. **Regressions against 0.5.4.** Check:
   - playback through the JS resolver, with its fallback to the Python helper;
   - adoption of URLs IINA opened itself, including the 10 s watchdog and pass-through;
   - live chat, with the new chat-timing delay and Live/Manual/Auto modes;

   - Go Live: seek versus reload (`GO_LIVE_REACH_SECONDS`, the reload's end-file skip), resuming playback, and the pill's live-edge rule (cache end within 8 s of the playhead);
   - Open Stream (⌃⌘O window, sidebar +);
   - sign-in and sign-out;
   - settings persistence;
   - plugin identity isolation (stable, beta, dev);
   - that QA mode is never packaged in beta or stable builds (`scripts/build.py`).
4. **Data loss or user-visible breakage on upgrade from 0.5.4.**

  ## Remaining and new findings, ranked

  ### High

  1. Signed URLs still cross an unredacted host boundary — R1 #1. src/player.js:1321 still passes the full URL to IINA’s setString, which logs the value at debug level
     (https://github.com/iina/iina/blob/v1.5.1/iina/MPVController.swift#L849-L853). src/live-clock.js:118 still passes the signed URL to a host API that embeds it in
     invalid/disallowed-URL exceptions (https://github.com/iina/iina/blob/v1.5.1/iina/JavascriptAPIHttp.swift#L116-L125). The JS allowlist narrows that error path; it does not
     change the logging sink. Fix: use a playback boundary that keeps the signed address out of IINA’s property logs, or require host redaction; validate clock destinations before
     calling native HTTP. Test: use synthetic secret markers and check native logs and errors with debug logging enabled. This finding remains open under the original no-disclosure
     requirement, independently of whether #57 is treated as release debt.

  2. Auto freezes a delay, not the video’s chat position — R1 #7. src/chat-timing.js:98 retains a fixed delay, but src/player.js:777 still calls reveal with wall-clock Date.now().
     Once an item ages past that fixed delay, it appears even if the video has not advanced. The integrated probe held the playhead at 134 and observed row count=0 → 1 while still
     paused. Fix: drive Auto eligibility from the mapped playhead time and hold that point when video stops advancing. Leave Live and Manual semantics separate. Test: freeze the
     playhead past estimator confidence loss, enqueue a message after the frozen video time, advance wall time beyond the retained delay, then resume. The row must remain hidden
     until the playhead reaches it.

  ### Medium

  3. A late old-file end-file still breaks the Go Live transaction — R1 #9. src/player.js:1438 marks the transaction loading inside on_load; src/player.js:1524 interprets any
     subsequent end-file as replacement failure and clears busy. IINA invokes the hook on its mpv event queue
     (https://github.com/iina/iina/blob/v1.5.1/iina/MPVController.swift#L1112-L1125), but defers the plugin’s event callback to main without a file ID or reason
     (https://github.com/iina/iina/blob/v1.5.1/iina/MPVController.swift#L1241-L1247). In a managed window, the hook can therefore run before JS sees the old file’s end, even if mpv
     emitted that end first. The probe then observed playing → stopped and 1 → 2 loadfile calls before any replacement file-loaded. The candidate test at
     tests/r1-player-golive.test.js:157 checks only eventual recovery. Fix: don’t end a pending replacement on an unattributed end-file; use matching file-loaded, a reliably
     attributable failure, or the timeout. Test: deliver old-file end on both sides of the hook and issue Go Live or change quality before file-loaded; neither order should permit a
     second replacement or show a false failure.

  4. A retired controller can still revoke the shared login; an unrelated retire can suppress a sign-out result — new. src/player.js:1560 leaves the sidebar rendered and omits
     player-closed; src/player.js:534 has no active-controller guard on forgetAuth. In the probe, a live stream retired to a local file with an inactive sidebar that still showed
     auth:ready. Its Sign Out sent auth-forget, and the broker issued a mocked revoke and stopped a second window’s chat. Closing the local-file window sent no player-closed.
     Separately, global.js:297 registers even an unknown label on disconnect and calls auth.stop() whenever the audience is empty. An unrelated label’s disconnect during a pending
     revoke caused the requester’s auth-forgotten reply to disappear, including its revocation-failure warning. Fix: make retired sidebar actions inert, separate controller
     retirement from core closure, and do not stop the broker on a disconnect that removed no audience member. Capture the requesting session across await auth.forget() so a reply
     cannot land on a successor controller. Test: live → local → close with a delayed sidebar action, and a failed revoke on one label while another, non-participating label
     retires.

  5. The new controller can accept the old controller’s overlay messages — new. src/player.js:314 resets liveRun for every controller; src/player.js:644 uses that number as the
     batch fence. Two successive live sources on the same core both issued session 2. A deliberately delayed batch from the first session was accepted and displayed on the second.
     The same check gates moderation batches. The probe establishes acceptance, not that native WebKit delivers this ordering. Fix: allocate transport sessions monotonically across
     the core’s lifetime, or include a controller epoch in every overlay status and batch. Test: deliver old-session message, clear-all and status events after the second overlay is
     ready; all must be ignored.

  6. Managed windows still mutate IINA’s event state on the hook queue — R1 #8. The adopted path now yields, but src/player.js:1417 still deactivates a managed controller
     synchronously if its next file is foreign. The replay probe observed event.off before the hook returned. IINA calls out concurrent access to its event-listener state as a crash
     risk (https://github.com/iina/iina/blob/v1.5.1/iina/MPVController.swift#L1241-L1247). Fix: put managed foreign-file teardown on a main-thread turn too. Test: import or acquire
     replay in a plugin-created window, replace the file with local media, and assert no event.off occurs on the hook stack.
